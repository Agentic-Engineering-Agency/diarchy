## Rulings

Every `Ruling:` I made (also in the plan and the SDD ledger):
1. Ruling: `StepState` is `pending | ok | actionRequired | failed`; commands and the action button live on `ChecklistStep.commands/.action` — cost if wrong: trivial rename.
2. Ruling: "first non-empty host" = LAN first, then Tailscale — cost if wrong: ssh-copy-id hint names the other host.
3. Ruling: Moonlight pairing host = `diarchy-ssh --route lan -- true` ok → LAN host, else Tailscale host (the bash route function is not callable) — cost if wrong: pair against a worse route; one function.
4. Ruling: streaming-only actions (`uinput-access`, `lid-policy`) never block the KVM checklist; the KVM probe never passes `--streaming`; before starting Streaming the app probes with `--streaming` and refuses while a `required` action is pending (accepted by Main/t2) — cost if wrong: Streaming start gated incorrectly.
5. Ruling: config render writes the stored `DIARCHY_HOST_KEY_ALIAS` raw (empty stays empty) — cost if wrong: none (effective alias computed on read).
6. Ruling: error reasons and check order are spec §4.5 / bash loader `0de47bb` (Main's ruling, supersedes my initial catalogue) — cost if wrong: none.
7. Ruling: step 3 on ssh exit 255: `Permission denied` → `actionRequired` with ssh-copy-id; `REMOTE HOST IDENTIFICATION HAS CHANGED`/`Host key verification failed` → failed with a clear "key changed" message (fail closed); anything else → failed with the route reason — cost if wrong: wrong hint for an unusual ssh failure.
8. Ruling: Moonlight `pair` exit code ignored; pairing success is decided only by the agent's `stream pair` `{paired:true}`; the Moonlight child is terminated (TERM, 5 s, KILL) after the agent answers (spec §9.3 update) — cost if wrong: none (spec-mandated).
9. Ruling: subagents run as an implementer agent and a reviewer agent (pinned `anthropic/claude-sonnet-5-5`, thinking high), created in the user-level agent definitions directory, because the task tool has no model parameter and the default agent failed with a 401 — cost if wrong: none.
10. Ruling: parallel dispatch per Main (Task 7 ∥ Task 10; Task 9 split 9a/9b/9c) — cost if wrong: commit races (mitigated by per-path commits; none occurred).
11. Ruling: the remote install script keeps the two-`mv` swap of `payload` (spec §7 layout; an atomic exchange needs a layout change) — cost if wrong: a millisecond window with no host payload dir; recovers on re-run.
12. Ruling: transient `Cambiando de modo…` for `.transitioning` (additive to §8.2) — cost if wrong: a literal §8.2 string check sees one extra transient string.
13. Ruling: `Quit` stops an active Streaming session (TERM→KILL + host `stream stop`) and leaves KVM as is — cost if wrong: KVM stays enabled after quit.
14. Ruling: after pairing writes the Lan Mouse config the app runs `diarchy-kvm off` (best effort, result ignored) so the next `on` starts Lan Mouse with the new config — cost if wrong: one extra local command.
15. Ruling: checklist step 1 also requires the clipboard bridge / file portal components `diarchy-kvm on` needs (`diarchy-clipboard-bridge`, `diarchy-file-portal-receiver`, `diarchy-file-portal-send`, `diarchy-config.sh`, `diarchy-route.sh`, the Diarchy File Portal app binary) — stricter than §8.4's literal list (spec silent); cost if wrong: a Mac without them is told to install instead of failing at the first KVM click.
16. Ruling: selecting KVM while `degraded` runs `diarchy-kvm off` first, then the normal off→kvm sequence; `diarchy-kvm status` reports `degraded` right after a normal install — cost if wrong: one extra command.
17. Ruling: menu open runs only the cheap local mode refresh; the full 7-step network checklist runs at launch, when Settings appears and after actions; `Off` stays selectable while the checklist runs — cost if wrong: checklist state shown in the menu can be stale until Settings is opened.
18. Ruling: `stream pair` has a 40 s timeout (agent retries 20 s plus route selection) vs 15 s for other commands — cost if wrong: slower failure report.
19. Ruling: streaming is refused before any host call when `diarchy-stream` or Moonlight is missing on the Mac; a Moonlight/`diarchy-stream` exit within 5 s of spawn yields an "exited immediately" error — cost if wrong: a user who quits Moonlight within 5 s also sees that message.
20. Ruling: the Settings `Window` is suppressed at launch with `.defaultLaunchBehavior(.suppressed)` on macOS 15+ and an event-driven AppDelegate fallback on macOS 14 (two `App` types chosen by `@main Launcher`, because `SceneBuilder` cannot branch on `#available`) — cost if wrong: Settings could appear at launch on macOS 14 (not testable here; macOS 27 verified: no window at launch).
21. Ruling: the MenuBarExtra popover is left to SwiftUI after `Settings…`/`Diagnostics…` (it lingers beside the Settings window until the user clicks elsewhere). `orderOut` dismissed it but made the next status-item click a no-op; `performClick` on the status button did not dismiss it (both observed in real smoke runs) — cost if wrong: cosmetic.
22. Ruling: the system segmented `Picker` was replaced by a small custom mode control because the system control greys the selected label when disabled and cannot disable single segments — cost if wrong: no arrow-key navigation (minor accessibility gap).
